# TMGF — актуальная спецификация 0.0.0.1

Русская браузерная футбольная RPG: собственный клуб, матч против бота, развитие футболистов и карьера через вымышленные дивизионы. Технологии — HTML, CSS, ES modules, Canvas 2D и Web Audio. Runtime не требует внешних библиотек, CDN, аккаунтов или игрового сервера. Публикация — GitHub Pages; версия увеличивается только последним компонентом и только на выпуск.

Основание переработки: [REWORK-0.0.0.1.md](REWORK-0.0.0.1.md). Подтверждённые наблюдения оригинала и ограничения: [ORIGINAL-FLOW.md](ORIGINAL-FLOW.md), [ORIGINAL-AIR.md](ORIGINAL-AIR.md). Наблюдения ROM и численные правила TMGF — разные источники: поле, шаговый режим, радиусы, цены и коэффициенты этой игры не выдаются за извлечённые формулы ROM.

## Состояния матча

11 игроков с каждой стороны; поле 25 × 15. Основное состояние хранится в `match.phase`, ход матча — в `match.status`.

| Фаза | Управление и переход |
| --- | --- |
| `field` | Стрелки/WASD — один ортогональный шаг владельца мяча. Нет броска на дриблинг или обязательного меню после шага. Пробел открывает `command`. Сближение автоматически переводит в `encounter`. |
| `command` | Добровольное меню паса, навеса, удара, спецудара, комбинации и восстановления. Отмена возвращает в `field`. |
| `target` | Отдельный экран поля. Любая точка выбирается мышью или стрелками; Enter/кнопка выполняет пас либо навес. Отмена возвращает в меню, из которого начат выбор. Клик на обычной миникарте игрока не перемещает. |
| `encounter` | От одного до трёх близких защитников. Сначала назначаются индивидуальные действия, затем разрешается весь план. |
| `air` | Верховой эпизод: выход к мячу, борьба, приём/пропуск/удар. Пользователь делает свой встречный выбор. |
| `keeper` | Удар бота по нашим воротам: пользователь выбирает ловлю или отбивание кулаком. Удар нашей команды встречает бот-вратарь. |

`status` принимает `playing`, `halftime`, `finished`. Матч длится 90 игровых минут, после 45-й наступает перерыв с частичным восстановлением сил. Продолжение перерыва запускается отдельной кнопкой. Завершённый результат применяется к карьере ровно один раз; отдельная кнопка получает награду и возвращает в клуб.

Один шаг или завершённый игровой эпизод продвигает время на минуту. Меню, движение курсора и подготовка индивидуальных планов времени не расходуют. Начатый удар бота ждёт ответа вратаря; начатый верховой эпизод доводится до решения. Исход вычисляется до короткой постановки и сохраняется; после неё игра автоматически показывает следующую фазу. Ввод на время постановки блокируется, повторного подтверждения результата нет.

Когда мяч у бота, свободная фаза продвигается примерно раз в 650 мс. Это работает только на видимом экране матча и останавливается при выборе пользователя, уходе в клуб и скрытой вкладке. Свободные шаги человека не ждут повтора катсцены. Удержание клавиши не создаёт очередь повторных шагов.

## Индивидуальные планы

Во встрече отображаются имена, номера, внешность и роли всех защитников. Текущий участник выделен. В атаке дриблинг назначается очередному защитнику; пас, навес или удар завершают построение плана. Например, «дриблинг первому → пас при следующем → точка передачи» разрешается в этом порядке. Уже назначенный дриблинг не отменяется переходом к пасу.

В защите пользователь отдельно назначает отбор, перехват, блок либо ожидание каждому нашему участнику. План бота фиксируется заранее и не раскрывается ни текстом, ни процентом прогноза. После последнего приказа защиты проверки выполняются последовательно. Потеря мяча или успешный перехват прекращают оставшуюся цепочку. Неподходящий приём снижает эффективность, но не гарантирует автоматический промах.

Броски d100, шанс, имя участника, результат и факторы показываются после разрешения в диалоге и журнале. Seed и состояние генератора сохраняются. Обычные вероятностные проверки ограничены 3–95%; свободный приём без защитника может быть детерминированным.

## Характеристики и энергия

Отдельные показатели 1–99: удар, пас, дриблинг, контроль мяча, отбор, перехват, блок, игра в воздухе, прыжок, сила, скорость, выносливость и реакция вратаря. Рост задаётся в сантиметрах. Энергия 0–100 отделена от выносливости; усталость влияет на исполнение. Нельзя сворачивать технику или защитные действия в один общий показатель.

| Действие | Расход энергии |
| --- | --- |
| Свободный шаг | 0,8 |
| Дриблинг во встрече | 8 за каждого назначенного соперника |
| Пас / навес | 8 / 14 |
| Удар / спецудар | 18 / 30 |
| Дуэт / трио | 26 / 34 у владельца мяча; по 18 у каждого партнёра |
| Отбор / перехват / блок | 4 у действующего защитника |
| Удар головой / с лёта / приём / пропуск | 12 / 12 / 8 / 0 |
| Активная воздушная защита / ожидание | 9 / 0 |
| Ловля / отбивание кулаком | 5 / 0 |

Цены видны до выбора; непосильные действия блокируются. «Восстановить силы» возвращает энергию команде и отдаёт мяч сопернику. Совместный приём требует одного или двух доступных партнёров в радиусе семи шагов, у каждого должно быть не менее 18 энергии. Завершение матча полностью восстанавливает команду.

Навес нацелен в область. Кандидаты в радиусе четырёх шагов выбираются по скорости, дистанции и усталости; защитника рядом может не быть. При наличии защитника отдельный выход к мячу даёт преимущество в борьбе. Рост, прыжок, сила, воздух и усталость сравниваются до исполнения. Проигранная борьба отменяет удар. Для головы важен воздух, для удара с лёта — удар и контроль, для приёма — контроль. Бесплатные пропуск и ожидание оставляют выход при нехватке энергии.

## Карьера и сохранение

В каждом из четырёх дивизионов четыре клуба и два круга — шесть матчей. Первые два повышаются, последние два могут понижаться. Чемпион высшей лиги получает трофей. После сезона высшей лиги доступны национальный кубок и, для первых двух клубов, кубок чемпионов; кубковые ничьи разрешаются упрощёнными пенальти.

Все одиннадцать игроков получают опыт после матча. На уровнях 2, 4 и 6 выдаётся очко развития. Ветки «Завершитель», «Связующий», «Страж неба» имеют три ранга: спецудары, дуэт/трио и воздушная защита соответственно. Имена клуба и футболистов, страна, лиги, соперники и кубки редактируются между матчами.

`localStorage` хранит карьеру и незавершённый матч после изменений, включая курсор и ещё не разрешённые приказы. JSON проходит валидацию; экспорт/импорт переносит прогресс между браузерами. Импорт и удаление требуют явного подтверждения. Имена ограничены по длине и выводятся как текст. Перезагрузка не пересчитывает уже завершённый бросок. Облачных сохранений нет.

## Визуал и проверка

Единый 16-битный стиль: тёмно-синий фон, светлые прямоугольные панели с двойной рамкой, янтарные акценты, синие и красные формы, моноширинный системный шрифт. Сцена 320 × 180 масштабируется без сглаживания и с сохранением пропорций. В матче — крупные фигуры, маленькая карта, HUD и нижнее окно диалога; административной боковой панели нет. Внешность каждого футболиста сохраняется между профилем, бегом, встречей и последовательностью действий. Графика и синтезированный звук собственные, без ресурсов Tecmo. Звук выключен по умолчанию; поддержаны мобильное управление, клавиатура и reduced-motion.

Проверки охватывают свободный шаг без случайного броска, границы поля, меню и курсор без расхода времени, планирование нескольких участников, остановку цепочки после потери, передачу в область, воздушные этапы, вратаря, энергию, перерыв/финал, карьеру и сохранения. Полные симуляции проверяют завершение матчей. Браузерная проверка проходит весь цикл управления, восстановление после перезагрузки и мобильный экран. После публикации проверяется публичный GitHub Pages.

За пределами версии: офсайды, нарушения, замены, трансферы, многопользовательский режим и сюжетная кампания. Каталог названий приёмов не означает отдельную реализованную механику каждого названия.
